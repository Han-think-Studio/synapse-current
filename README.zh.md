# Synapse mini

小模型会忘记一个项目的形状。Synapse mini 把形状交给 Python 保存，**每次只让模型填一个
空位。**

它可以独立运行，运行时依赖只有一个，而且**它本身不需要模型才能工作。**

## 它做什么

1. **plan** —— 把一个想法变成确定的文件清单。同样的想法进去，同样的清单出来。
   不用模型，不联网。
2. **check** —— 读取一个已存在的文件夹，报告哪些必需文件里确实写了内容。
3. **demo** —— 在不写入任何文件的前提下，判定一份「路径→内容」的提案。

`check` 和 `demo` 会打印 JSON 回执，逐个文件说明通过与否以及原因；
`plan` 打印确定性的计划。

## 试一下

```
python _mini/synapse_mini.py plan _mini/examples/local_docs_search.md --preset software
python _mini/synapse_mini.py demo --idea _mini/examples/local_docs_search.md \
    --preset software --content-json _mini/examples/local_docs_search_fill.json
```

只要有任何一个必需文件是空的、是模板、或者不存在，第二条命令就会以非零码退出。

## Windows 便携式检出

公开 mini 版本包含会检测自身所在文件夹的启动器，因此可以移动检出目录，或从
任意当前目录启动。先双击运行 [`setup.bat`](setup.bat)，然后用
[`run.bat`](run.bat) 检查记录的示例，或用 [`run-core.bat`](run-core.bat)
执行确定性计划检查。如果 Python 3.12 虚拟环境不存在或无效，启动器会在检出目录旁
自动准备；其中不包含开发机器的固定路径。

**不运行任何东西也想先看结果**，就打开 [`evidence/`](evidence/live-idea2-nemotron-generated-20260916/README.md)：
那是一次实机运行产出的工作目录，文件原样保留。

**怎样写出一个能产出可用结构的想法**，见[指南](_mini/examples/HOWTO.zh.md)。
那是用你的语言而不是用代码写的那一部分。

想自己生成内容的话，需要使用支持 strict JSON Schema 响应格式的 OpenAI 兼容服务 ——
LM Studio、llama.cpp、vLLM：

```
python _mini/fill_with_local_model.py --idea _mini/examples/local_docs_search.md \
    --preset software --model 你的模型ID --out fill.json
```

## 为什么会有这个东西

这个领域的主要押注是**规模**：更大的模型、更多的训练、周围需要更少的脚手架。这个押注
一次又一次地兑现了，而这里没有任何东西是在论证**它押错了**。

2026 年 5 月，被问到谷歌处在什么位置时，这家公司的 CEO 说，在通用能力上 —— 文本、
多模态、推理 —— 他们很强，但在 **agentic coding**，也就是工具调用、指令遵循、长跨度任务
上，**"a bit behind at this moment"**。他把原因之一归于没能拥有那种工作得以作为数据回流
的**入口**，并点名了别人家的编程工具正是拥有它的那一方。

来源：[节目列表](https://podcasts.apple.com/us/podcast/our-field-trip-to-google-i-o-a-sit-down-with/id1528594034?i=1000769070660)
确认了 2026 年 5 月 22 日的节目以及 Sundar Pichai 作为嘉宾。关于编程差距和数据回流入口的
概述已与这份[公开文字稿](https://bidclub.ai/zh/e/hard-fork-live-part-2-dylan-field-standing-out-i)对照。

一种读法，这是关于渠道的故事。另一种读法，这是关于**差距由什么构成**的故事。
**稀缺的并不是通用能力。** 稀缺的是一个长任务在能力**周围**所需要的一切：一组能撑到
最后的指令、不会悄悄挪动的前提、已经定过什么的记录。**那就是结构，而它很薄。**

所以这边走了相反的方向。**他们朝模型去了，这边朝结构去了 —— 而且在那之前已经走了
一段时间。**

真正把它琢磨出来的地方，是一个**长篇创作项目**：耗时数月，早期做下的决定在很久以后
仍必须成立。在那里，**逐句来看没有什么是难的。** 难的是**前提不能漂移**，而一个被要求
攥住这些前提的模型，最终会在不吭声的情况下改掉其中一条。

**这是个人的押注而非被证明的结论**，下注的理由是这些：

**更少的浪费。** 一个能跨项目成立的结构，不必为每个项目重建。文件清单、职责和检查写
一次就反复使用，**每次新的只有内容。**

**能累积的工作。** 修订、在做的文件和记录**都有地方可去，而结构会说明是哪里**。当它是
一个文件而不是一种习惯，对它的改动就是**可见的、可评审的、可回退的** —— 进展不再是
某个人必须记住的东西。

**一条模型不越过的边界。** 真正拍板的是这一条。**当模型可以改写的区域被明确标出，
它之外的一切就是靠构造安全的，而不是靠盯着。** 而且事后读结果的人，**不必再去分辨
哪些是约定好的、哪些是临场发挥的。**

**模型要扛的更少。** 一个只被要求写一个空位、且那个空位只有一个职责的模型，**不必同时
攥着整个项目的形状**；运行更短、更便宜、也更好读。**注意力落在正事上，而不是落在重建
「这件正事原本是什么」上。**

**先把这些铺好，不是在有意思的那部分之前先付的一笔额外成本，而是让那部分变得够得着。**

所以这里把结构写下来。**这个选择早于任何一个具体的模型，也会活得比它们每一个都久：**
模型变强了，同一份契约之下文字变好；模型很小，同一份契约之下文字变朴素。
**两种情况都不需要谁再从头推导一遍这个项目原本是什么。**

## 它是怎么工作的

把整个项目丢给一个小模型，要它把前后都对上，它会丢线索：某条约束被悄悄丢掉，某个文件
写成了别的用途，某一节把上一节又说了一遍。

这里的解法是**不问**。**文件清单、每个文件的职责、它们的顺序，以及校验，都由 Python
拥有。** 模型只被要求做一件事：在这个空位的职责是这样时，写出放进这个空位的文字。
从不要求它记住整个项目、做决定，或者宣布什么已经完成。

所以无论想法是一个文档检索工具、一套会议记录系统，还是一部小说，**都在同一份契约
之下**被结构化。它们都不需要模型把整件事记在脑子里 —— 因为结构里本就没有一样东西
是该由模型来记的。

由此引出两条规则，它们都是承重的：

**模型的输出是提案。** 模型返回的任何东西都不会直接改变状态。填充脚本以退出码 0
表示*这次运行结束了*，绝不表示*结果是好的*。那个判定由另一条命令做出，而且用的是
完整系统所用的那个检查器本身，不是它的副本。

**确定性内核在什么都没装的情况下也能跑。** 不要模型，不要 GPU，不要向量数据库，
不要云服务。所以在你还没对模型做任何决定的阶段，`plan` 就已经有用；内核的测试也
因此能在 CI 里运行。

## 它是怎么搭起来的

五块，而**其中哪一块被允许出错**，就是整个设计。

| | 它拥有什么 |
|---|---|
| `synapse/core/` | 规划器和内容检查器。决定**有什么存在**，以及**什么算写过了** |
| `domain_packs/_presets/` | 五个预设：一份文件清单，每个文件配一行职责说明 |
| `_mini/synapse_mini.py` | 命令行。**导入**内核而不是重写它，自己不做任何判定 |
| `_mini/fill_with_local_model.py` | **唯一**和模型说话的文件。不拥有任何判断 |
| `_mini/examples/` | 十个实测示例及其填充结果，另有一个独立的英文示例 |

**最后两块之间的分界值得读两遍。** 填充脚本被**声明为不可信**：模型有时会回答错的问题、
中途停下、或者返回一段道歉而不是文档，所以那个脚本只负责把回来的东西渲染出来，并以退出码 0
表示这次运行结束了。做判定的是检查器，而且是**规范检查器本身** —— 不是一份会和它渐行渐远
的副本。

## 它检查什么

当每个必需文件的每个标题下面都有写下的内容时，`demo` 会给出 READY。
**这是一项结构性检查，而且它对自己的边界很清楚。**

它不判断内容在你的领域里对不对，也不授予任何「可以应用」的权限。那由人来决定 ——
**这正是提案和已确认状态在这里是两样东西、而不是同一样东西的两个时刻的原因。**

## 它拦住了什么

十个示例想法，由一个本地模型在一台机器上填充，记录在
[`_mini/examples/RESULTS.zh.md`](_mini/examples/RESULTS.zh.md)：
**10 个 READY，0 个被拦下，125 个文件。**

在这个过程中，结构**在内容抵达文件之前拒绝了 39 次回答**，而这 39 次全都在后续尝试中
写了出来。**其中 14 次针对的是内容检查根本看不见的问题** —— 用它所在文件的名字当小节
标题，或者用了别的文件已经用过的标题。它们既不空也不是模板；若是放过去，**每一个都会
成为一个完成的文件** —— 一个读起来和其它文件一模一样的文件。

让这件事成立的有四点，**四点都不显然**，所以值得明确写出来：

**真正的提示词是 schema。** 用自然语言要求小模型写出有实质内容的段落，得到的是道歉
和一句话。在响应 schema 的 body 字段上声明 `minLength`，段落就出来了。
**在受约束解码下，模型遵守的并不是请求里的措辞。**

**一个不可能失败的检查不是检查。** 被截断的回答带着「已完成」的标签抵达，比完全没有
截断检查更糟，**因为人们会信任它。** 截断从服务方自己给出的停止原因里读取，**在每一条
分发路径上**，是报告而不是推断。

**受约束解码保证的是形状，不是意思。** schema 约束的是容器，对里面那串字符只字未提 ——
形状正确的合法 JSON 里，仍然可能装着一整篇 Markdown 文档，或者句子中途冒出来的响应
格式本身。这些由填充脚本 —— **那个被允许出错的一侧** —— 拒绝，而不是由检查器拒绝；
检查器回答的是它被问到的那个问题。

**重试必须改变请求。** 被截断的回答得到更大的预算。被拒绝的回答得到检查器算出的理由，
并且**保留此前收到的每一条理由**。把同样的话再发一遍是许愿，不是第二次尝试。

## 环境要求

Python 3.12 和 `pyyaml`。清单就这些，而且**如果一个只装了这一项的裸解释器跑不完
全部命令，发布包就不会被构建出来。**

## 状态

**发布前。** 确定性内核、各项检查和命令行都已稳定，并由**不需要模型、GPU 或网络**的
测试覆盖。

它所切自的那套更大的系统是内部使用的，不在此提供。这里不做性能宣称，也不做质量宣称 ——
上面说的那些检查是结构性的，**结构性正是它们要做的事。**
