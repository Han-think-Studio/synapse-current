# 제약과 경계

## 파일 형식 및 데이터 품질

- CSV 파일에는 최소한 날짜, 가맹점명, 금액 열이 있어야 한다.
- 카드사별로 열 이름과 날짜 형식이 다르므로 사용자가 한 번 매핑을 지정해야 한다.
- 같은 구독이라도 가맹점명이 조금씩 다르게 찍힐 수 있으므로(예: 'NETFLIX.COM', 'NETFLIX 1234') 문자열 비교 시 유연성을 허용한다.
- 결제 주기는 월간·연간이 대부분이며 주간도 드물게 존재하므로 주기 탐지 로직에 변수를 두어야 한다.
- CSV 파일에 누락된 열이나 잘못된 데이터가 있을 경우 처리를 보류하거나 사용자에게 알린다.

## 보안 및 외부 연결 제한

- 은행이나 카드사 계정에 직접 접속하지 않는다. 사용자가 내려받은 로컬 파일만 처리한다.
- 결과 리포트나 데이터를 외부로 전송하지 않는다. 네트워크 호출이 전혀 없다.
- 금융 조언, 절약 권유, 해지 안내 등 해석이나 권고 기능을 제공하지 않는다. 숫자와 사실만 제시한다.
- 영수증 이미지, PDF 명세서 등은 읽지 못한다. CSV 형식의 거래내역만 지원한다.

## 기능 범위 및 결과물 제한

- 사용자가 지정한 CSV 파일 내에서 반복 결제를 찾아 구독 후보로 묶는다.
- 각 후보별로 첫 결제일, 최근 결제일, 주기, 평균 금액, 누적 지출을 계산한다.
- 금액이 중간에 상승한 경우 인상 시점과 인상폭을 별도로 표시한다.
- 최근 결제가 예상 주기를 넘겨 끊긴 경우 '종료 추정'으로 분리하여 표시한다.
- 결과는 화면 표와 CSV 리포트 두 가지 형태로 제공한다.
