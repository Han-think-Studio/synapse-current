# 검증 계획

## 입력 데이터 검증

- CSV 파일이 존재하는지 확인하고, 파일 인코딩이 UTF-8 또는 EUC-KR인지 확인합니다.
- 필수 열(날짜, 가맹점명, 금액)이 포함되어 있는지 스캔합니다. 누락된 열이 있으면 사용자에게 매핑 요청을 중단시킵니다.
- 날짜 형식이 다양할 수 있으므로, 여러 일반적인 패턴(YMD, MDY, DMY 등)을 자동 감지하거나 사용자 지정 매핑을 적용한 후 파싱에 실패하는지 검증합니다.

## 구독 패턴 인식

- 동일한 가맹점명(정규화 후)으로 그룹화하여 반복 결제 여부를 확인합니다.
- 각 그룹 내에서 일정한 주기(월/년)가 유지되는지, 금액 편차가 일정한 범위 내에 있는지 분석합니다.
- 중간에 금액이 상승한 경우를 감지하고, 인상 시점과 폭을 정확히 식별하여 표시할 수 있는지 검증합니다.
- 최근 결제일이 예상 주기를 초과하면 '종료 추정' 라벨을 붙이는 로직이 정확하게 동작하는지 테스트합니다.

## 출력 리포트 정확성

- 계산된 구독 항목(첫 결제일, 최근 결제일, 주기, 평균 금액, 누적 지출 등)이 CSV와 화면 표에 정확히 반영되는지 확인합니다.
- 인상 시점과 종료 추정 여부가 사용자에게 명확히 구분되어 표시되는지 검증합니다.
- 최종 리포트 파일이 올바른 형식(CSV 인코딩, 열 순서)으로 저장되며, 외부 네트워크 접속 없이 로컬만으로 처리되었는지 확인합니다.
