# Synapse mini

작은 모델은 프로젝트의 모양을 잊어버립니다. Synapse mini는 **모양을 Python이 들고 있고
모델에게는 한 번에 한 칸만** 시킵니다.

단독으로 돌고, 런타임 의존성은 하나이며, **동작하기 위해 모델이 필요하지 않습니다.**

## 무엇을 하는가

1. **plan** — 아이디어를 결정적인 파일 목록으로 바꿉니다. 같은 아이디어를 넣으면
   같은 목록이 나옵니다. 모델도 네트워크도 쓰지 않습니다.
2. **check** — 이미 있는 폴더를 읽어서, 필수 파일 중 어디에 실제로 쓰인 내용이
   있는지 보고합니다.
3. **demo** — 경로→내용 제안을 아무것도 쓰지 않고 판정합니다.

`check`와 `demo`는 파일마다 통과/미통과와 그 이유를 적은 JSON 영수증을 내고,
`plan`은 결정적인 계획을 출력합니다.

## 해보기

```
python _mini/synapse_mini.py plan _mini/examples/local_docs_search.md --preset software
python _mini/synapse_mini.py demo --idea _mini/examples/local_docs_search.md \
    --preset software --content-json _mini/examples/local_docs_search_fill.json
```

두 번째 명령은 필수 파일 중 하나라도 비었거나 템플릿이거나 없으면 0이 아닌 코드로
끝납니다.

## Windows 포터블 체크아웃

공개 mini판에는 실행 파일 자신이 있는 폴더를 감지하는 실행기가 포함되어
있습니다. 따라서 체크아웃 폴더를 옮기거나 현재 작업 폴더가 어디든 실행할 수
있습니다. 먼저 [`setup.bat`](setup.bat)을 한 번 실행하고, 기록된 예시는
[`run.bat`](run.bat), 결정적인 계획 검사는 [`run-core.bat`](run-core.bat)를
사용하세요. 실행기는 Python 3.12 가상 환경이 없거나 잘못되었을 때 체크아웃
폴더 옆에 자동으로 준비하며, 개발자 PC의 고정 경로를 포함하지 않습니다.

**아무것도 돌리지 않고 결과부터 보려면** [`evidence/`](evidence/live-idea2-nemotron-generated-20260916/README.md)를 여세요.
실제 실행 한 번이 만들어 낸 작업 폴더가 파일 그대로 들어 있습니다.

**쓸 만한 구조가 나오는 아이디어를 어떻게 쓰는지**는 [안내서](_mini/examples/HOWTO.ko.md)에
있습니다. 코드가 아니라 당신 언어로 되어 있는 부분입니다.

직접 채워 보려면, strict JSON Schema 응답 형식을 받아들이는 OpenAI 호환
엔드포인트를 사용해야 합니다 — LM Studio, llama.cpp, vLLM:

```
python _mini/fill_with_local_model.py --idea _mini/examples/local_docs_search.md \
    --preset software --model 사용할-모델-ID --out fill.json
```

## 왜 만들었는가

이 분야의 주된 베팅은 **규모**입니다. 더 큰 모델, 더 많이 학습한 모델, 주변에 받침대가
덜 필요한 모델. 그 베팅은 여러 번 성과를 냈고, 여기 있는 어떤 것도 **그것이 틀렸다는
주장이 아닙니다.**

2026년 5월, 구글이 어디쯤 있냐는 질문에 그 회사의 CEO는 범용 능력 — 텍스트, 멀티모달,
추론 — 에서는 앞서 있지만 **agentic coding**, 즉 도구 사용과 지시 따르기와 긴 호흡의
작업에서는 **"a bit behind at this moment"**라고 답했습니다. 그런 작업이 데이터로 돌아오는
**표면**을 갖지 못했던 것을 이유의 하나로 들며, 그 표면을 가졌던 것으로 남의 코딩 도구를
지목했습니다.

출처: [에피소드 목록](https://podcasts.apple.com/us/podcast/our-field-trip-to-google-i-o-a-sit-down-with/id1528594034?i=1000769070660)이
2026년 5월 22일 에피소드와 Sundar Pichai의 참여를 확인합니다. 코딩 격차와 데이터가 돌아오는
표면에 대한 요지는 이 [공개 transcript](https://bidclub.ai/zh/e/hard-fork-live-part-2-dylan-field-standing-out-i)를 대조해 작성했습니다.

한쪽으로 읽으면 유통 이야기입니다. 다른 쪽으로 읽으면 **격차가 무엇으로 이루어져 있었는가**에
대한 이야기입니다. **모자랐던 것은 범용 능력이 아니었습니다.** 모자랐던 것은 긴 작업이
그 능력 **주변에** 요구하는 것 전부였습니다 — 끝까지 살아남는 지시 묶음, 조용히 움직이지
않는 전제, 이미 정해진 것의 기록. **그것이 구조이고, 그 구조가 얇았습니다.**

그래서 이쪽은 반대로 갔습니다. **그들은 모델을 향해 갔고, 이쪽은 구조를 향해 갔습니다.
그전부터 한동안 그러고 있었습니다.**

그것을 실제로 풀어낸 자리는 **장편 창작 프로젝트**였습니다. 몇 달이 걸리고, 앞에서 내린
결정이 한참 뒤에도 그대로 서 있어야 하는 일입니다. 거기서 **문장 단위로 어려운 것은
없습니다.** 어려운 것은 **전제가 흔들리면 안 된다**는 것이고, 그것을 들고 있으라고 시킨
모델은 결국 **말없이 하나를 고쳐 놓습니다.**

**증명된 판단이 아니라 개인적인 베팅**이고, 그렇게 건 이유는 이렇습니다.

**낭비가 줄어듭니다.** 프로젝트를 건너 유지되는 구조는 매번 다시 만들지 않습니다.
파일 목록과 역할과 검사는 한 번 적어 두고 재사용하며, **매번 새로운 것은 내용뿐**입니다.

**일이 쌓입니다.** 수정과 보완, 작업 중인 파일, 기록이 **갈 자리가 있고 구조가 그 자리를
말해 줍니다.** 구조가 습관이 아니라 파일이면 그것을 바꾼 일이 **보이고, 검토되고, 되돌릴
수 있습니다** — 진전이 누군가 기억하고 있어야 하는 것이기를 그만둡니다.

**모델이 넘지 않는 경계가 생깁니다.** 결정적이었던 것이 이겁니다. **모델이 고쳐도 되는
영역이 명시되어 있으면, 그 바깥은 감시가 아니라 구성으로 안전합니다.** 그리고 나중에
결과를 읽는 사람이 **어디까지가 합의된 것이고 어디부터가 즉흥인지 가려낼 필요가
없습니다.**

**모델이 짊어질 것이 줄어듭니다.** 목적 하나짜리 칸 하나를 요청받은 모델은 **프로젝트의
모양까지 들고 있지 않습니다.** 실행이 짧아지고, 싸지고, 읽기 쉬워집니다.
**본격적인 작업에 주의가 가고, 그 작업이 무엇이었는지를 복원하는 데 가지 않습니다.**

**이것을 먼저 깔아 두는 것은 재미있는 부분 앞에 치르는 비용이 아닙니다. 재미있는 부분에
닿을 수 있게 만드는 것입니다.**

그래서 구조를 적어 둡니다. **그 선택은 특정 모델보다 먼저 있었고 각각의 모델보다 오래
남습니다.** 모델이 좋아지면 같은 계약 아래 글이 좋아지고, 모델이 작으면 같은 계약 아래
글이 담백해집니다. **어느 쪽도 이 프로젝트가 무엇이었는지를 처음부터 다시 추론하게
만들지 않습니다.**

## 어떻게 동작하는가

작은 모델에게 프로젝트 전체를 주고 앞뒤를 맞춰 달라고 하면 실을 놓칩니다.
제약 하나가 조용히 사라지고, 파일이 제 역할이 아닌 내용으로 채워지고, 한 절이
바로 위 절을 되풀이합니다.

여기서는 **묻지 않는 쪽**을 택했습니다. **파일 목록과 각 파일의 역할, 순서, 그리고 검증을
Python이 소유합니다.** 모델에게는 하나만 시킵니다 — 이 칸의 역할이 이것일 때 그 칸에
들어갈 글. 프로젝트를 기억하라고도, 결정하라고도, 끝났다고 선언하라고도 하지 않습니다.

그래서 아이디어가 문서 검색 도구든 회의 기록 시스템이든 소설이든 **같은 계약 아래**
구조화됩니다. 어느 쪽도 모델이 전체를 머리에 들고 있을 필요가 없습니다.
구조에 관한 것 중 **모델이 들고 있어야 할 것이 애초에 없기** 때문입니다.

여기서 두 가지 규칙이 따라 나오고, 둘 다 구조를 떠받칩니다.

**모델의 출력은 제안입니다.** 모델이 돌려준 것은 무엇도 상태를 직접 바꾸지 않습니다.
채우기 스크립트는 종료 코드 0을 *실행이 끝났다*는 뜻으로만 씁니다. *결과가 괜찮다*는
뜻으로는 절대 쓰지 않습니다. 그 판정은 별도의 명령이 내리고, 그것은 전체 시스템이
쓰는 검사기의 사본이 아니라 바로 그 검사기입니다.

**결정적 코어는 아무것도 깔지 않은 상태에서 돕니다.** 모델도, GPU도, 벡터DB도,
클라우드도 없이. 그래서 모델에 대해 아무것도 정하지 않은 단계에서도 `plan`이 쓸모가 있고,
코어 테스트가 CI에서 돕니다.

## 어떻게 짜여 있는가

다섯 조각이고, **그중 어느 것이 틀려도 되는가**가 설계의 전부입니다.

| | 무엇을 소유하는가 |
|---|---|
| `synapse/core/` | 계획 생성기와 내용 검사기. **무엇이 존재하는지와 무엇을 쓰인 것으로 볼지**를 정합니다 |
| `domain_packs/_presets/` | 프리셋 5종. 파일 목록에 한 줄짜리 목적문이 붙은 것 |
| `_mini/synapse_mini.py` | CLI. 코어를 **다시 만들지 않고 가져다 쓰며**, 스스로는 아무것도 판정하지 않습니다 |
| `_mini/fill_with_local_model.py` | 모델과 말하는 **유일한** 파일. 아무 결정도 소유하지 않습니다 |
| `_mini/examples/` | 라이브 실행 예시 10개와 별도 영어 샘플 1개, 그리고 그 배포용 fill |

**마지막 둘 사이의 경계를 두 번 읽으세요.** 채우기 스크립트는 **믿지 않는 쪽으로 선언**되어
있습니다. 모델은 가끔 다른 질문에 답하고, 중간에 멈추고, 문서 대신 사과문을 돌려줍니다.
그래서 그 스크립트는 돌아온 것을 렌더링하고, 종료 코드 0을 **실행이 끝났다**는 뜻으로만 씁니다.
판정은 검사기가 하고, 그것은 **정본 검사기 그 자체**입니다 — 어긋날 수 있는 사본이 아니라.

## 무엇을 검사하는가

`demo`는 모든 필수 파일의 모든 제목 밑에 실제로 쓰인 내용이 있을 때 READY라고 합니다.
**구조에 대한 검사이고, 자기 경계에 대해 분명합니다.**

내용이 그 도메인에서 맞는지는 판정하지 않고, 무엇을 반영해도 좋다는 권한을 주지 않습니다.
그건 사람이 정합니다 — **제안과 확정 상태가 여기서 같은 것의 두 시점이 아니라 서로 다른
것인 이유**가 그겁니다.

## 무엇을 잡아내는가

아이디어 열 개를 로컬 모델 하나로 기계 한 대에서 채운 기록이
[`_mini/examples/RESULTS.ko.md`](_mini/examples/RESULTS.ko.md)에 있습니다 —
**READY 10, 막힌 것 0, 파일 125개.**

그 과정에서 구조가 **파일에 닿기 전에 39건을 거부**했고, 39건 전부 다음 시도에서 쓰였습니다.
**그중 14건은 내용 검사로는 볼 수 없는 문제**였습니다 — 자기가 들어갈 파일의 이름을 절 제목으로
쓴 것, 다른 파일이 이미 쓴 제목을 다시 쓴 것. 비어 있지도 템플릿도 아니므로, **그대로 뒀다면
전부 완성된 파일이 되었을 것입니다.** 다른 파일들과 똑같이 읽히는 파일로요.

그게 되게 만드는 것이 네 가지이고, **넷 다 당연하지 않아서** 적어 둘 값이 있습니다.

**스키마가 진짜 프롬프트입니다.** 작은 모델에게 말로 "내용 있는 절을 써라"라고 하면 사과문과
한 줄짜리가 옵니다. 응답 스키마의 body 필드에 `minLength`를 선언하면 절이 옵니다.
**제약 디코딩 아래의 모델이 따르고 있는 것은 요청의 문장이 아닙니다.**

**실패할 수 없는 검사는 검사가 아닙니다.** 잘린 답이 완결됐다는 딱지를 달고 도착하는 것은
잘림 검사가 아예 없는 것보다 나쁩니다. **사람들이 믿기 때문입니다.** 잘림은 제공자가 준
중단 사유에서 읽고, **모든 디스패치 경로에서** 추정이 아니라 보고로 다룹니다.

**문법 제약은 모양을 보장하지 의미를 보장하지 않습니다.** 스키마는 그릇을 제약하고 그 안의
문자열에 대해서는 아무 말도 하지 않습니다 — 모양이 맞는 유효한 JSON이 마크다운 문서 한 편을,
또는 응답 형식 자체를 문장 도중에 담고 있을 수 있습니다. 그런 것은 검사기가 아니라
**채우기 스크립트 — 틀려도 되는 쪽 —** 가 거부합니다. 검사기는 받은 질문에 답합니다.

**재시도는 요청을 바꿔야 합니다.** 잘린 답에는 더 큰 예산을 줍니다. 거부된 답에는 검사기가
산출한 이유를 주고, **이미 받은 이유를 전부 들고 갑니다.** 같은 말을 다시 보내는 것은
재시도가 아니라 소원입니다.

## 요구 사항

Python 3.12와 `pyyaml`. 목록은 이게 전부이고, **그것만 깔린 맨 인터프리터에서 모든 명령이
돌지 않으면 릴리스가 만들어지지 않습니다.**

## 상태

**출시 전입니다.** 결정적 코어와 검사와 CLI는 안정적이고, **모델도 GPU도 네트워크도 없이
도는 테스트**가 덮고 있습니다.

이것을 잘라낸 더 큰 시스템은 내부용이고 여기서 제공하지 않습니다. 성능 주장도 품질 주장도
하지 않습니다 — 위에 적은 검사들은 구조에 대한 것이고, **구조가 그것들이 맡은 일입니다.**
