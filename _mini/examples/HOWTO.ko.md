# 쓸 만한 구조가 나오는 아이디어 쓰는 법

**코드는 영어로 짭니다. 입력에 들어가는 사고는 아닙니다.** 이 문서는 그쪽 이야기입니다.

여기 있는 전부가 입력 하나로 돕니다 — 원하는 것을 자기 언어로 적은 몇 문단. 나오는 구조는
그 문단만큼만 쓸모가 있고, **쓸 만한 프로젝트가 나오는 설명과 제목 더미가 나오는 설명의 차이는
작고, 배울 수 있고, 프롬프트 요령과는 아무 상관이 없습니다.**

## 무엇을 넣고 무엇이 나오는가

파일 하나를 씁니다. 그러면:

```
python synapse_mini.py plan examples/local_docs_search.md --preset software
```

가 그것을 고정된 파일 목록으로 바꿉니다 — 모델도 네트워크도 없이, 매번 같은 목록으로.
그다음 모델이 각 파일의 본문을 쓰고, 정본 검사기가 돌아온 것이 **실제로 쓰인 내용인지 빈 껍데기인지**
판정합니다.

**모델이 끼기 전에 세 가지가 정해집니다.** 어떤 파일이 있는지, 각각이 무엇을 맡는지, 무엇을
끝난 것으로 볼지. 그게 방법의 전부입니다. 모델에게는 한 칸씩 글만 시키고, 프로젝트를 기억하라고도
끝났다고 선언하라고도 하지 않습니다.

## 되는 아이디어의 다섯 부분

이 폴더의 아무 파일이나 열어 보세요. 전부 같은 모양입니다. 템플릿이라서가 아니라,
**구조를 세우기에 충분한 최소 형태**라서 그렇습니다.

1. **기술이 아니라 대상을 부르는 제목.**
   `이미지 속 글자 번역해서 다시 넣기`이지 `OCR + MT 파이프라인`이 아닙니다.
2. **지금 실제로 처한 상황.** 오늘 뭘 하고 있고 왜 안 되는지. 두세 문장.
   **모델이 다른 문제를 지어내는 걸 막는 게 이 부분입니다.**
3. **대신 원하는 것.** 한 문단.
4. **중요한 조건.** 네다섯 줄. **여기가 하중을 받는 부분입니다.** 아래 참고.
5. **먼저 할 것.** 한 문장 — 뭘 먼저 하고 뭘 나중으로 미룰지.
   없으면 아무도 요청하지 않은 로드맵이 나옵니다.

## 이걸 할 가치가 있는지 가르는 규칙 하나

**검사할 수 있는 조건은 규칙이 됩니다. 검사할 수 없는 조건은 소원으로 남습니다.**

구조에는 "항상 지켜야 하는 것"을 적는 파일이 있고, 각 파일이 실제로 쓰였는지 묻는 검사가 있습니다.
**둘 다 소원으로는 아무것도 못 합니다.**

| 소원 | 규칙 |
|---|---|
| 번역을 정확하게 한다 | 고유명사 표기는 전 회차에서 하나로 고정하고, 바꾸면 기록을 남긴다 |
| 오류 처리를 잘한다 | 글자를 못 읽은 영역은 비워 두지 않고 못 읽었다고 표시한다 |
| 빠르게 한다 | 바뀐 파일만 다시 색인한다. 전체 재읽기는 느린 경로가 아니라 결함이다 |
| 환각을 막는다 | 근거 문단이 없으면 답하지 말고 "없음"이라고 말한다 |
| 데이터를 안전하게 지킨다 | 문서 원문은 이 PC를 벗어나지 않고, 임베딩도 로컬에서 만든다 |

오른쪽이 더 자세해서가 아닙니다. **반증 가능해서**입니다 — 결과를 보고 그렇게 됐는지 아닌지
말할 수 있습니다.

### 두려운 실패를 적으세요

이 예시들 중 가장 센 문장은 이미지 번역 아이디어의 이겁니다.

> 글자가 들어갈 자리보다 번역문이 길면 줄여 쓰지 말고 넘쳤다고 표시한다.
> **잘린 대사를 조용히 내보내는 것이 가장 나쁘다.**

이 한 문장이 세 가지를 한꺼번에 합니다. **실패를 이름 붙이고, 편한 우회로를 금지하고,
나쁜 결과 둘 중 어느 쪽이 더 나쁜지 말합니다.** 이걸로 세운 구조는 검사할 수 있고,
"보기 좋게 만든다"로 세운 구조는 못 합니다.

여기 예시 전부에 그런 줄이 최소 하나씩 있습니다. 당신 프로젝트가 이것들과 전혀 달라도
예시를 읽을 값이 있는 이유가 그겁니다.

## 검사가 말해 주는 것과 말해 주지 않는 것

`demo`와 `check`는 모든 필수 파일의 모든 제목 밑에 쓰인 내용이 있을 때 READY라고 합니다.
**그건 바닥입니다.**

비었는지, 템플릿인지, 없는지는 말해 줍니다. 내용이 **맞는지, 충분한지, 말이 되는지는 말해 주지
않습니다.** [RESULTS.ko.md](RESULTS.ko.md)의 열 번 실행에서 **검사기가 아예 볼 수 없는 문제로
14건이 거부**됐습니다 — 파일 자기 이름을 절 제목으로 쓴 것, 다른 파일이 이미 쓴 제목을 다시 쓴 것.
**그 14건은 전부 그냥 통과했을 것들입니다.**

그래서 순환은 이렇습니다. 아이디어를 쓰고, 생성하고, 돌아온 것을 읽고, 아이디어를 고치고,
다시 생성합니다. **검사는 당신이 볼 가치가 없는 경우를 걸러서, 볼 가치가 있는 것에 눈이
가게 합니다.**

## 다시 돌리기

계획은 결정적입니다. 같은 아이디어와 프리셋이면 같은 파일 목록과 같은 계획 id가 나옵니다 —
어느 기계에서든, Python과 `pyyaml` 말고는 아무것도 없이. **이게 일회성이 아니라 출발점으로 쓸 수
있게 만드는 지점입니다.** 아이디어에서 세 줄을 고치고 다시 계획하면 무엇이 움직였는지 정확히
보입니다.

시키지 않으면 디스크에 아무것도 쓰지 않습니다. `plan`은 출력만 합니다. `demo`는 제안을
만들지 않고 판정합니다. `check`는 이미 있는 폴더를 읽고 건드리지 않습니다.
**아직 정하는 중일 때 망가질 상태가 없습니다.**

## 예시들, 그리고 각각이 보여주는 것

일부러 서로 다른 종류의 일로 흩어 놓은 흔한 요청들입니다. **각 라이브 실행 예시가 서로 다른
종류의 조건을 보여줍니다** — 하나가 아니라 열 개인 이유가 그겁니다. `idea.md`는 라이브 실행이
아닌 별도 영어 샘플입니다.

| 예시 | 프리셋 | 보여주는 조건의 종류 |
|---|---|---|
| `local_docs_search.md` | software | 근거 없이 답하기를 거부하기 |
| `codebase_assistant.md` | software | 모든 출력에 출처를 요구하기 |
| `youtube_digest.md` | automation | 한 일을 되풀이하지 않고 재개하기 |
| `image_translation.md` | automation | 실패를 숨기지 않고 표시하기 |
| `meeting_notes.md` | automation | 확신이 없을 때 일부러 빈칸을 남기기 |
| `webnovel_translation.md` | content | 이미 내린 결정을 바꿀 때 기록하기 |
| `persona_chatbot.md` | content | 설정을 이력과 분리해 두기 |
| `local_model_bench.md` | research | 비교 전에 무엇이 같아야 하는지 고정하기 |
| `prompt_ab_test.md` | research | 결과를 보기 전에 기준을 적기 |
| `workflow_audit.md` | general | 관측만 후보로 인정하기 |
| `idea.md` | software | 영어 입력에서도 같은 구조가 나오는 것 |

**자기 문제에 제일 가까운 걸 복사해서 내용만 바꾸고 모양은 유지하세요.**

## 직접 시작하기

```
cp examples/local_docs_search.md my_idea.md
# 내용을 고친다
python synapse_mini.py plan my_idea.md --preset software
```

프리셋: `general` `software` `research` `content` `automation`.
모르겠으면 `general`이 가장 작고 파일을 가장 적게 더합니다.
