# 怎样写出一个能产出可用结构的想法

**代码是用英文写的，往里输入的那份思考不是。** 这一页讲的正是后者。

这里的一切都跑在一份输入上：你用自己的语言写下的几段话，说明你想要什么。产出的结构，有用到
什么程度，完全取决于那几段话；而**一份能产出可用项目的描述和一份只产出一堆标题的描述，差别很小、
可以学会，并且和提示词技巧毫无关系。**

## 输入什么，产出什么

你写一个文件。然后：

```
python synapse_mini.py plan examples/local_docs_search.md --preset software
```

把它变成一份固定的文件清单 —— 不用模型，不联网，每次都是同一份清单。接着模型写出每个文件的
正文，规范检查器判定回来的东西究竟是**写过的内容还是一个空壳**。

**在模型介入之前，三件事已经定了**：有哪些文件、每个文件负责什么、什么算完成。这就是方法的全部。
模型只被要求写文字，一次一格，从不被要求记住整个项目，也不被要求宣布它完成了。

## 一个能用的想法的五个部分

随便打开这个目录里的任何一个文件，它们的形状都一样。不是因为它是模板，而是因为它是
**足以撑起一个结构的最短形式**。

1. **标题说的是那个东西，不是技术。**
   「图片里的文字翻译后放回去」，而不是「OCR + MT 流水线」。
2. **你现在实际所处的状况。** 今天你怎么做的，为什么不行。两三句话。
   **正是这一段挡住了模型去发明另一个问题。**
3. **你想要的替代方案。** 一段。
4. **重要的条件。** 四到六行。**这是承重的部分**，见下文。
5. **第一步。** 一句话：先做什么，什么留到以后。
   没有它，你会得到一份没人要过的路线图。

## 决定这件事值不值得做的那一条规则

**能检查的条件会变成规则。不能检查的条件只会停留为愿望。**

结构里有一个文件专门写「必须始终成立的事」，还有一项检查会问每个文件是否真的被写过。
**这两者对一个愿望都无能为力。**

| 愿望 | 规则 |
|---|---|
| 把翻译做准 | 专有名词在整部连载里只用一种写法；改动必须留下记录 |
| 好好处理错误 | 文字没读出来的区域标记为「未读出」，而不是留空 |
| 做得快 | 只对变动过的文件重新建索引；全量重读是缺陷，不是慢路径 |
| 别产生幻觉 | 找不到依据段落时必须回答「没有」，而不是给出答案 |
| 保证数据安全 | 文档原文不离开本机；向量也在本地生成 |

右边那一列并不是更详细，而是**可证伪**：你可以看着结果说出它有没有发生。

### 把你害怕的那种失败写下来

这些示例里最有力的一句，来自图片翻译那一个：

> 如果译文比要放进去的位置长，不要压缩，而要标记为溢出。
> **把被截断的台词悄悄发出去是最坏的结果。**

这一句同时做了三件事：**给失败命名、禁掉那个省事的绕路、并说明两种坏结果里哪一种更坏**。
由它搭起来的结构可以被检查；由「做得好看一点」搭起来的不行。

这里每个示例都至少有一句这样的话。即使你的项目和它们毫不相干，这也是它们值得一读的原因。

## 检查会告诉你什么，不会告诉你什么

当每个必需文件的每个标题下面都有写下的内容时，`demo` 和 `check` 会给出 READY。
**那是地板。**

它会告诉你某个文件是空的、是模板、或者不存在。它**不会告诉你内容是否正确、是否完整、是否说得通**。
在 [RESULTS.zh.md](RESULTS.zh.md) 记录的十次运行里，**有 14 次回答因为检查器根本看不见的问题
而被拒绝** —— 用文件自己的名字当小节标题，或者用了别的文件已经用过的标题。
**这 14 个本来都会顺利通过。**

所以循环是这样的：写想法、生成、读回来的东西、改想法、再生成。
**检查负责筛掉不值得你花注意力的情况，好让你的注意力落在值得的那些上。**

## 再跑一次

计划是确定性的。同样的想法和预设，产出同样的文件清单和同样的计划 id —— 在任何机器上，除了
Python 和 `pyyaml` 什么都不用装。**这正是它能当作起点而不是一次性产物的地方**：改掉想法里的
三行，重新 plan，就能准确看到什么动了。

不叫它写，它就不往磁盘上写任何东西。`plan` 只打印。`demo` 在不创建的前提下判定一份提案。
`check` 读取你已有的目录且不碰它。**在你还在拿主意的阶段，没有会被弄坏的状态。**

## 这些示例，以及每一个在展示什么

它们是普通的需求，刻意分散在不同种类的工作上。**每个实测示例展示的是不同种类的条件** ——
这就是为什么有十个而不是一个。`idea.md` 是独立的英文示例，不是第十一个实测运行。

| 示例 | 预设 | 它展示的条件类型 |
|---|---|---|
| `local_docs_search.md` | software | 没有依据就拒绝回答 |
| `codebase_assistant.md` | software | 要求每一条输出都带出处 |
| `youtube_digest.md` | automation | 不重复已做的事而继续 |
| `image_translation.md` | automation | 标记失败而不是藏起来 |
| `meeting_notes.md` | automation | 不确定时刻意留空 |
| `webnovel_translation.md` | content | 改动一个已下的决定时留下记录 |
| `persona_chatbot.md` | content | 把设定和对话历史分开保存 |
| `local_model_bench.md` | research | 比较之前先固定什么必须一致 |
| `prompt_ab_test.md` | research | 在看到结果之前写下判定标准 |
| `workflow_audit.md` | general | 只承认观测到的东西作为候选 |
| `idea.md` | software | 同样的结构在英文输入上也成立 |

**把最接近你问题的那个复制过来，换掉内容，保留形状。**

## 开始你自己的

```
cp examples/local_docs_search.md my_idea.md
# 编辑它
python synapse_mini.py plan my_idea.md --preset software
```

预设：`general` `software` `research` `content` `automation`。
拿不准就用 `general`，它最小，加的文件最少。
